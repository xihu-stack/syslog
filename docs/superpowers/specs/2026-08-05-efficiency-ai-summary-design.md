# 2026-08-05 效率监控页改为 AI 摸鱼总结

## 背景
原效率页是数字表(摸鱼次数/最长跨度/工作%/各类/活跃天数/在岗时段)+ 顶部 Alert KPI。
问题:这些数字是粗略代理,且"次数/工作%"口径易误读;运营真正想知道的是"谁、什么时候、干了什么影响效率"。

## 目标
把效率页从"数字表"改为"AI 自然语言总结":近7天、逐人卡片、AI 自选值得说的人/行为。

## 设计(已获批)

### 移除
- 顶部 Alert(最长跨度≥30 N人)
- 数字表(摸鱼次数/最长跨度/工作%/各类/活跃天数/在岗时段)

### 新增
- **后端 `GET /api/efficiency/summary`**(缓存10分钟):
  1. 查近7天 WEB 工时(9-12,14-18)事件,`slack_category` 命中 → 按员工聚成会话(时段/类别/域名/次数)
  2. 预筛控成本:只取近7天摸鱼≥3次的人,压缩成文本(每人一行:"张三 08-05 10:30 视频(bilibili)×3, 14:00 社交(weibo)×2")
  3. LLM prompt:挑出影响效率的行为,按人一句话总结(谁/时段/干了什么/多久或几次),只挑值得说的,忽略零星;只输出 JSON `[{employee, summary}]`
  4. 返回 `{items, msg?}`
- **前端 Efficiency 组件**:标题 + "生成 AI 摸鱼总结"按钮(按需调,不自动)+ 逐人卡片(姓名 + AI一句话),点卡片→画像

### 保留
- `/api/efficiency` 不动(仍供大屏 摸鱼人数/平均工作占比 tile 用)
- 大屏 tile 不变;摸鱼人数 tile 点击去掉 slackMin(新页面不用),改为 go('efficiency')

### 原则
- 挑选+措辞交 AI(prompt);会话聚合(事实)留代码。符合 [[ai-judgment-over-hardcode]]。
- AI 按需调用 + 10分钟缓存,控制成本/延迟。

### 待办/已知
- 大屏 摸鱼人数/平均工作占比 tile 仍是数字 KPI(与 AI 页不同形态),后续可再议是否也 AI 化。
